## Contract

All endpoints are relative to `/api/v1/admin/projects/{project_id}/sections`, using existing JWT authentication.

| Operation            | Method/path                                   | Generated contract                                         |
| -------------------- | --------------------------------------------- | ---------------------------------------------------------- |
| List/create          | GET/POST base                                 | PageSectionResponse; SectionCreate → SectionResponse (201) |
| Detail/edit/delete   | GET/PATCH/DELETE `/{section_id}`              | SectionResponse; SectionUpdate; DELETE 204                 |
| Section order        | PUT `/order`                                  | Reorder; 204                                               |
| List/attach media    | GET/POST `/{section_id}/media`                | PageSectionMediaResponse; SectionMediaInput (201)          |
| Edit/detach relation | PATCH/DELETE `/{section_id}/media/{media_id}` | SectionMediaUpdate; DELETE 204                             |
| Media order          | PUT `/{section_id}/media/order`               | Reorder; 204                                               |

Visibility is PATCH is_visible, not a separate endpoint. Media relations have no own UUID or role: identity is section_id/media_id. Media reorder uses **media_id** as OrderItem.id. Lists use items/total/limit/offset; all pages are loaded at 100 items per request. Generated contracts were regenerated byte-identically.

Common fields: section_type, nullable title (200 characters), nullable plain-text content (50000), sort_order (integer 0–2147483647), is_visible and media. Captions are nullable with a 255-character limit. Changing section_type is supported and validates the complete resulting section. No alignment, attribution, rich-text, external-video or split-ratio fields exist.

| Type     | Visible requirements           | Media compatibility/cardinality      |
| -------- | ------------------------------ | ------------------------------------ |
| TEXT     | Nonblank content               | None                                 |
| IMAGE    | One image                      | IMAGE, maximum one                   |
| GALLERY  | At least one image             | IMAGE, maximum 100                   |
| VIDEO    | One video                      | VIDEO, maximum one                   |
| MODEL_3D | One model                      | MODEL_3D, GLB UX policy, maximum one |
| QUOTE    | Nonblank content               | None                                 |
| SPLIT    | Nonblank content and one image | IMAGE, maximum one                   |

Hidden sections may be incomplete but still respect compatibility/cardinality. The editor requires some title, text or media before creating a hidden section. Frontend checks are UX only; FastAPI remains authoritative. GLTF remains disabled.

## Architecture

New sections and type selectors offer only Texto (TEXT) and Galería de imágenes
(GALLERY). Existing sections of other backend-supported types retain their current
type and editing support; their content is not converted or removed.

ProjectSectionsApi is a focused HttpClient service using API_BASE_URL, generated types and the shared ApiError parser. ProjectSections owns one authoritative list, loading/writing state and editor selection. Existing content remains during refresh. Writes are serialized in the UI and failed ordering reloads backend state.

SectionEditor uses one typed Reactive Form and explicit SECTION_POLICY configuration for the seven types. Common operations are shared; there are no duplicated type editors or generic form framework. Failed initial detail/media loading cannot save an empty replacement. 422 locations map to controls; 400/409/permission/network/rate-limit errors use safe contextual messages. Failed normal saves preserve drafts; Retry-After is retained through ApiError and error presentation.

## Media and ordering

The existing ProjectMediaPicker gained an optional fixed media-type input. Project Media usage is unchanged. Sections reuse this picker, MediaApi.detail and MediaPreview; they never implement another upload manager. Models additionally check the established GLB MIME UX policy.

Local additions, removals, captions and media ordering remain drafts until Save. Create/PATCH sends the complete media collection atomically, supported by SectionCreate/SectionUpdate. This allows replacing a required image or changing type without an invalid intermediate visible state. Removing relations never deletes global media assets or R2 objects. Individual attach/update/detach APIs remain available and contract-tested.

When only existing unchanged media order differs, Save uses media/order with asset UUIDs. Failed order writes reload authoritative section/media state. Section Move up/down controls commit final order per action, sequentially batching at 100 entries when required, then reload. Failed/partially applied batches also reload. No intermediate pointer requests exist.

Previews use existing private delivery/blob and SSR-safe MediaBrowser mechanisms. No URLs are constructed from storage keys, no signed URLs are persisted, videos do not autoplay, and no 3D viewer was added.

## UX, accessibility and rendering

The inline editor focuses its type control after loading through an Angular browser-only render hook. Native labels, fieldsets, associated field errors, visible focus, status/alert messages and existing native confirmation dialogs are used. Keyboard Move up/down controls provide ordering without drag-only interaction. No CDK, PrimeNG or rich-text dependency was necessary.

Dirty section drafts participate in ProjectEditor's CanDeactivate confirmation. Local cancellation or switching editors asks before discarding changes. Incompatible save/delete/reorder actions are blocked; logout/session expiry retains the existing auth behavior.

No new route was added. Sections stay inside the lazy project-editor chunk, outside the initial public graph. Protected SSR routes continue RenderMode.Client with no private HTML. Browser-only focus hooks do not run on the server.

## Validation

`npm run test:sections:browser` uses Chrome CDP and private local development credentials. Two PNGs, a browser-recorded WebM and a minimal valid GLB are uploaded through Phase 4. The smoke creates all seven types, edits text, reorders sections/gallery media, reloads persistence, previews private media, changes visibility and deletes a section. It checks 375/768/1024/1440 widths, no extra PUT during association and no JWT to R2.

Cleanup uses APIs: sections/relations first, project soft delete, temporary media delete. The existing narrowly scoped development verifier confirms PostgreSQL and R2 definitive/staging cleanup. Soft-delete and terminal technical history remain according to backend policy.

Unit coverage includes all API operations and pagination, every type, compatibility, duplicate submits, local gallery changes, persisted media order, nullable fields/type changes, initial-load failure, 422/409/network errors, authoritative order recovery, discard confirmation and deletion conflicts. Authentication, media, project and shell regression tests remain intact.
